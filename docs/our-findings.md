# What we measured on our own 559-page wiki, with numbers, limits, and which statements are only hypotheses.

All numbers are from 2026-11-05 and trace to our wiki page `wiki-retrieval-bench` and the result files `bench-2026-11-05-baseline-summary.md`, `bench-2026-11-05-A-vs-C.md`, `bench-2026-11-05-A-vs-B.md`. Model for all bench runs: a small, cheap one (Claude Haiku class). Questions are real owner questions, mostly Russian; the wiki itself is English only.

## 1. Wiki miner: how agents really moved (not a bench)

Read-only script over Claude Code transcripts of 14 sessions that touched the wiki (559 pages, `index.md` of 120,632 bytes). 150 questions found.

- Median one wiki call per question; none needed 8 or more calls. Agents read single pages.
- `index.md` was opened 12 times in 4 sessions, usually in pieces. Five sessions read three or more pages without opening it first.
- 60 of 559 pages were read at all in these sessions. A sample, not proof the rest is useless.
- Some large pages (29 to 42 KB) were read again and again.
- No search reached the three-session evidence threshold, so there is no data yet for "missing article".

## 2. Baseline A: the wiki as it is

Frozen copy of 559 pages, nine real questions with owner-confirmed gold pages, tools limited to Read, Grep, Glob, at most 14 turns.

- First single run: right page opened for 7 of 9 questions; `index.md` read first in 2 of 9 runs; total cost about $0.09. Seven of nine runs began with Grep or Glob (source: `wiki-retrieval-bench`).
- Three runs per question (27 runs): right page found in 22 of 27; mean 6.4 steps per run; mean input about 188k tokens. Seven questions found 3 of 3; the "Panther" bot question 1 of 3; the "groups" question 0 of 3.

## 3. Variant C: search tool plus generated aliases

A stdlib-only field-weighted BM25 search tool (title, slug, aliases, "questions this page answers", summary, headings, body) with a side file of aliases and questions kept outside `wiki/`. The aliases were generated by a model from page text only, not from the bench questions.

- Right page reached in 16 of 27 runs (A: 22 of 27).
- Mean 3.2 steps per run (A: 6.4); mean input about 148k tokens (A: 188k).
- The agent used the search tool in 27 of 27 runs.
- Offline, without any agent: BM25 on the raw Russian question, top-5 hit: no aliases 2 of 9, generated aliases 4 of 9.
- Cause seen in traces: the agent trusts the top hit and stops. Question 18: gold page ranked 2nd (score 60.2 against 61.4). Question 3: gold not in the top 4 because of noisy alias matches on an unrelated page.

So C was faster and cheaper but found the right page less often. The aliases are a draft, not applied to the live wiki.

## 4. Variant B: not measured

Variant B (aliases written into three page summaries) failed in 26 of 27 runs on a usage limit. Those zeros are not results. B has no number.

## 5. Failure causes seen in the baseline

- **Nickname missing.** The owner's nickname for a bot appears on other pages but not on the page that describes the bot. The agent searched the nickname and opened no page; why the results led nowhere was not examined.
- **Owner's word versus wiki's word.** "Groups" against "combos" and "tiers"; the agent read "groups" as chat groups. The question also had little context, so part of the miss is the question.
- **Overlapping pages.** Five pages on updates; the agent opened four to assemble an answer.

## 6. Limits

- Nine questions, one model, three runs in the A and C comparison. A direction, not a result.
- A hit means a gold page was opened. It does not mean the answer was correct. Correctness is not measured yet.
- Gold pages were first chosen from what the agent opened, then checked and corrected three times; this can bias toward pages agents already find.
- Two gold pages were written or changed during the very tasks, so the bench measures the present wiki, not the wiki at question time.
- Questions are shown without the session context the owner had.
- The agent still loaded the owner's global settings. Same in every variant, so comparisons are fair, absolute numbers are not clean.
- A temporary API refusal hit five questions in the first run; they were rerun and passed.

## Sandbox caveat for variant C

In our A-versus-C runs Bash was not strictly confined to the search tool: some C agents ran `cat`, `ls` or `cd ... &&` through Bash (we counted a page read by `cat` as a hit). `run_bench.py` now passes `--permission-mode dontAsk`, which in a one-question retest refused a stray Bash command. The 16-of-27 and 3.2-step numbers were measured before that change, so treat C as having had a slightly wider toolset than A.

## Hypotheses, not findings

- A better first line per page (summary and aliases) is probably worth more than a smaller `index.md`.
- Agents search rather than browse in general. We saw it in one wiki and one model only.
- A search tool that returns a clearly ranked top hit with a confidence signal might fix the "trust the top hit" problem. Untested.

## 6. Additions of 2026-11-07 (offline, free; nine questions again, so read as direction)

**Stemmer and hub boost** (`eval_search.py`, generated aliases, top-3 hit share): the old 5-letter prefix 0.44; suffix-stripping stemmer 0.22; without aliases prefix 0.11, suffix 0.22. With one question worth 0.11 the stemmer difference is two questions either way, so neither is shown better; the prefix stays the default because it is the variant the agent runs were made with. Hub boost (more weight to pages many others link to): no change at 0.1 and 0.15, worse at 0.3 (top-3 hit 0.33). It stays off. Offline top-5 hit with aliases was 0.44 here, below what the agent reached by trying several searches, so the offline figure is a floor for the search tool, not for the agent.

**Lint of the live wiki** (`wiki_lint.py` on the 559 pages): 40 errors and 67 warnings (with the English-only check off; a first version counted 10 more links that were examples inside code, fixed after a clean-install test). Errors: 39 links to pages that do not exist (for example a page named `frontend` linked from several pages, and legal pages that were never created) and one page without a **Sources** line. Warnings: 52 pages that no other page links to, 15 without a "Related pages" section. Every page is listed in `index.md`. These were found by tool and not yet fixed; nobody has decided whether the missing pages should be created or the links removed. The English-only check reports 92 pages with Cyrillic text, which may be quoted owner wording or a real rule violation; not looked into.

**Measuring-tool defects found by another agent's run on its own wiki and fixed in v0.2** (the first outside use): a usage limit made the bench record questions as zero-step misses; hits were counted only for the `Read` tool, so reading through `cat` showed as a miss; `install.py` crashed on a cp1251 console when printing the diff against an existing `CLAUDE.md` that contained characters outside that code page (we reproduced it with `→`). The advice in `INSTALL.md` to set `PYTHONUTF8` was wrong with `-I`, which ignores that variable.

**Live test of v0.2 on our wiki** (4 gold questions, plain arm and search arm, Haiku, about $0.08 in total; too few runs for any comparison, it tested the tools). It found three defects that the unit tests had not:
1. The `[[page-name]]` example in the template `index.md` made `wiki_lint` report an error on a clean install. Links inside code are now ignored; the same fix removed 10 false "broken link" reports on our wiki (49 became 39).
2. A search-arm agent put several `--show` calls into one shell command; the bench recorded only the first, so a question could show "gold page opened" with "steps to first gold page: none". Every page printed by a command is now counted and the step number is computed from the full command, not the shortened one in the trace.
3. **The allow-list is not a sandbox.** With `--permission-mode dontAsk` and an allow-list naming only `python tools/wiki_search.py`, the agent still ran `grep` and `cat` through Bash (checked directly, also with user settings excluded). So the search arm has had a shell that the plain arm does not have. This affects our earlier A-versus-C comparison beyond the `cat` caveat above; `run_bench.py --shell` now gives the plain arm the same read-only shell, and `bench/README.md` says so.
Also seen: agents wrote `python -I tools/wiki_search.py`, and wrapped searches in `2>&1 | head`; both work. Resume (`--resume`) kept the two finished questions and ran only the rest.
